## 結論

課題三行棚卸しは点型資産にしか効かず、線型・過程型・定量型は別手段を要する ―― この前提はgit実測で裏づいた。実測により確定したのは次の通り。①**継続性（線型）はモジュール規模で実証された**。delivery（約3年）・dailyProcess（約2年強）が現行・稼働中の単独保守で、これは No505/507 の実装先と一致する（点と線が同一モジュールで重なった）。②ただし**リポジトリ／ディレクトリ規模の単独担当は裏づかない**（本人はどのトップレベルディレクトリでも最大6.9%）。③**AI駆動は「体制」としては堅い物証があるが、「運転過程」の一次資料は直近約4週間分のみ**で、「半年以上」の主張は未実証。④**RPA＝Toil削減（定量）はFPPリポジトリ外**で未取得のまま。残る取得対象は、AI駆動の古いログ所在確認とRPA数値集計の2つ。

## 1. 前提（証跡タイプ別4手段・実証済み）

資産には点型・線型・過程型・定量型があり、取得手段が異なる。課題三行で埋まるのは点型のみ、という当初の訂正はgit実測で確認された。

- 点型（一課題で完結）: 課題三行＋合意側1行
- 線型（数年の継続性）: 通期集計＋モジュール別移行点分析
- 過程型（AIの運転過程）: `.claude/`体制の棚卸し＋セッションログ抽出
- 定量型（削減件数・時間）: Mos-RPA数値集計

## 3. 確定した実績（職務経歴書に使える）

### 3-1. 点型（課題資料で実証済み）

- **説明力**（No507）: 梅・竹・松を工数の異なる条件付きトレードオフとして提示し、見送りも含め顧客に選ばせた構造が調査結果報告書に一次資料として残る。「竹に落ち着く」先読みを工数積算に織り込んだ提案設計を含む。留保: 採用決定（竹）は定例会の口頭合意で書面なし。
- **レガシー×モダン両刀**（No505/507＋実測）: Oracle基幹＋React/TypeScript＋ASP.NET Coreを単独横断。実測の拡張子分布（cs 2833／ts 1411／tsx 1105／rpx 163／sql 66）が併存を裏づける。
- **技術判断・AI出力の監査**（No505/507）: 前セッション混入の実名・EMPLOYEEIDの根拠不明記載を捕捉削除、既存キャッシュバグを直さず迂回、誤送信防止を最優先に据えたテスト設計、デプロイ順序非依存の防御、環境起因/コードバグの切り分け。

### 3-2. 線型（通期集計・移行点分析で確定）

**在籍・運用の継続**: cyclonist2（Nextage）で 2023-03〜2026-09、43か月中42か月稼働（空白は2024-05のみ）。累計 追加94,078行／削除55,776行／1,390ファイル。

**現行・稼働中の単独保守（実証の中核）**: モジュール別に直近窓のコミッタを測定した結果、以下2モジュールが「他者は数年前に途絶え、直近6か月も本人のみ、かつ本人が稼働中」と確定した。

- **delivery**（全レイヤー）: 他者最終コミット 2023-08-04。以降2026-09まで他者0件。約3年の単独保守で、2026-08〜09に稼働中（No505の実装先）。
- **dailyProcess**（全レイヤー）: 他者最終コミット 2024-06-13。以降他者0件。約2年強の単独保守で、2026-09に稼働中（No507の実装先）。

**単独責任だが間欠稼働**: PriceApproval（他者は数年前に途絶え単独責任だが、最終稼働2026-02で直近6か月は無稼働）。

**移行途上（単独と言い切れない）**: Schedule（直近12か月は複数人・直近6か月は本人のみ）。TopSalesはバックエンド（ServerActions/Models）が直近6か月 本人のみだが、**pages/topSalesは直近6か月も他者（mukuda）が関与**しており、機能一括では単独と呼べない。

**スコープの限界（誇張回避）**: リポジトリには本人以外に多数の作者が存在し、本人はどのトップレベルディレクトリでも支配的でない（Controllers 3.4%／ServerActions 6.8%／Models 4.6%／ClientApp 6.9%）。したがって「単独」は**担当モジュール規模でのみ成立**し、リポジトリ／ディレクトリ規模の単独担当ではない。

### 3-3. 点と線が重なったコア（最も defensible）

single-maintenance と確定した delivery・dailyProcess は、そのまま No505・No507 の実装先である。**課題資料（点型）とモジュール単独保守の継続（線型）が同一モジュールで一致**した。「この機能を開発期の共同から保守期の単独へ引き継ぎ、数年 単独で回し、直近も自分が実装している」という、点と線が噛み合った実績が確定している。なお delivery/dailyProcess は歴代シェアでは少数派（29%・20%）であり、累積比率だけ見れば脇役に見える。「歴代シェア」ではなく「開発期は共同・保守期以降は単独で継続」が正確な表現。

### 3-4. AI駆動の開発体制（物証として確定）

- **commit/push禁止設定**: `.claude/settings.json` の `permissions.deny` に `Bash(git push *)`・`Bash(git commit*)` が明記。co-author 0件の構造的理由であり、意図的にガバナンスされたAI運用の証跡。
- **`.claude/`体制**: agents 3（code-reviewer等）／commands 8／hooks 10（自動規約チェック: sql-lint・style-guard等）／skills 8／docs 11。「Claudeを使った」ではなく「AI駆動の開発環境を設計・運用している」ことの証跡。
- **案件との接続**: commands の `feasibility-survey` が No507（実現可能性・工数調査）、`bugfix` が No505 のブランチ `bugfix/…` に対応。ワークフローが実案件に接続している具体的裏づけ。

## 4. まだ取得が必要な情報

### 4-1. AI駆動の運転過程（古いログの所在）【過程型】

- 現状: セッションログは `~/.claude/projects/` 配下に存在するが、確認できる期間は 2026-08-12〜2026-09-08（約4週間・cyclonist2本体130件）のみ。
- 問題: career-direction.md の「半年以上手書きしていない」に対し、一次資料で裏づく期間は約1か月。「半年以上」は未実証で、現状 言えるのは「直近約4週間の運転過程が一次資料として残る」まで。
- 取得方法: より古いログの保管場所（バックアップ・別ディレクトリ・旧マシン等）の有無を確認する。無ければ主張を「直近約1か月」に合わせるか、体制側（`.claude/`・commit/push禁止＝2026-08以前から整備されていた証跡）で運用期間を間接的に補う。
- 補足: 「一行も手書きしていない」を前面に出すと、〈実運用者〉と〈AI依存で代替可能〉の両方に開くため、証明力は成果物ではなく運転過程（要件の二転三転をどう方向づけ、AI出力の破綻をどう捕まえたか）の側に置く。

### 4-2. RPA＝Toil削減【定量型】

- 現状: Mos向けEzAvaterプロジェクトで、FPP（cyclonist2）リポジトリ外。今回の集計対象外。
- 取得方法: 自動化シナリオ本数／自動化前の手作業時間／自動化後の所要時間／月次・年次の削減時間 を数値で集計する。SRE/基盤転職の求人が求める Toil削減の共通言語に、唯一 数値で応えられる柱。
- 切り分け: アドリブ性（仕様なしで回すオーナーシップ）は線型として、削減数値はこの定量型として、別軸で拾う。

### 4-3. 合意側1行【点型の補強・今後の運用】

- No505/507ともに、決定的な合意が書面に残っていない（職場の記録文化の問題）。説明力を立てる際、証跡が「提案側は文書・合意側は不在」の片肺になる。
- 今後の課題で三行を残す際、合意側1行（誰が・いつ・どのチャネルで承諾したか）を都度足す。career-direction.md 3章(4)の軽量記録に1項目追加する形。

## 5. 職務経歴書での表現（確定した書き方）

- **継続性**: 「特定業務システム（cyclonist2）を2023年3月から一貫して保守開発。うち delivery・dailyProcess の両機能は、開発期の複数人体制から保守期の単独担当へ移行し、それぞれ約3年・約2年強にわたり単独で保守運用を継続、直近も自身が実装している」
- **単独のスコープ**: 「（リポジトリ全体ではなく）担当機能モジュールの単独保守運用者」。多人数リポジトリ内で担当領域を単独で完結、と限定して書く。
- **時間軸の分離**: 〈在籍・運用の継続＝2023-03〜〉と〈AI駆動フェーズ＝2026年頃〜〉は別指標として分けて書く（「2026-01頃から」は後者を指す想定）。
- **AI駆動**: 「AI駆動開発の環境（エージェント・自動規約チェック・スキル・commit/push権限制御）を自ら設計・運用し、実装・調査フローに組み込んでいる」。体制として書き、「特定コミットがAI生成」「半年間AIで回した」は物証が揃うまで主張しない。
- **避ける表現**: 「システム全体を43か月単独運用」「歴代シェア〇%の主担当」「一行も手書きしていない」。いずれも実測または読み手の解釈で崩れる。
